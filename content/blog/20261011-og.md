## 使用场景

**开放图谱协议（Open Graph Protocol）** 的仅有作用是给社交媒体爬虫提供分享所需的必要信息。这样，当社媒用户向其他用户分享网址时，社媒可以根据爬取结果生成精美的分享内容，比如卡片。

如果你想看一看这张分享卡片可以长什么样，芒果帆帆最近在这里实现了一个[分析仪](/toy/playground/og)，供你娱乐。

关于开放图谱协议的更多规范和定义也在上述页面。

除此之外，使用开放图谱协议对网站的其他方面效果是比较有限的：

* 不会影响搜索引擎中页面的 SEO 排名。
* 无法代替 **`DC.xxx`** 规范，这是为科研等专业领域的数据分享所设计的类似协议，被学术期刊、政府文件、学术搜索引擎广泛使用。
* 无法代替 **`schema.org`** 规范，这是为网页的结构化数据分享所设计的协议，对于结构化数据（比如**电影的演职员表**）的支持程度远优于此协议。
* 不会影响浏览器的工作方式，也不会影响页面访客看到的内容。

## 分析仪工作方式

### 抓取页面

#### ❌前端抓取

我们都知道，在前端 :term-tip-javascript 中直接 fetch 一个其他的网站内容，有很大的可能会遇到[跨域错误](https://developer.mozilla.org/zh-CN/docs/Web/HTTP/Guides/CORS/Errors)。

简单来说，跨域错误出现在网站 A 尝试**未经授权地**访问网站 B 的内容时。

简单地继续说，未经授权的含义是：

* 网站 B 不允许自己的内容被其他网站任意访问。
* 如果网站 B 设置了允许访问的白名单网站，那么网站 A 不在白名单中。

关键在于，网站 B 的服务器本身不会在这一步拦截访问，而是在 HTTP 响应标头中指出有关的规则，这被称为**同源策略**。遵守网站 B 的同源策略并阻止网站 A 访问的是用户的**浏览器**。

同源策略可以在一定程度上保护用户免受恶意网站的攻击，这是一种重要的安全策略。虽然在这里，同源策略阻挡了我们在前端抓取目标网页的 HTML。

**不建议在浏览器层面关闭同源策略。** 一些浏览器的一些版本可能允许通过 flags 关闭同源策略，但不应该依赖这种规避，无论是作为用户还是作为 Web 开发者。

既然跨域错误发生在浏览器，这就意味着运行在浏览器的 JavaScript 抓取其他网站是走不通的。幸运的是我们并非别无选择，只要让抓取不在浏览器中进行就可以了。

#### ✅服务端抓取

芒果客栈在 :term-tip-cloudflare Worker 中实现了两个运行在云的端点，其中一个用于抓取目标页面的 HTML 并返回给浏览器中的 JavaScript。由于此端点与芒果客栈是同源的，因此浏览器不会拦截。

由于芒果客栈的当前架构为 :term-tip-nuxt ，这基本上只是在 `/server/api` 目录下实现两个 :term-tip-typescript 的事情。这样，作为网站 A 的分析仪向后端端点发起请求，附带网站 B 的 URL，由后端代为抓取，从而避免了浏览器拦截跨域。

顺便还能使用 :term-tip-prettier 对抓取得到的 HTML 文档进行格式化。

### 解析元数据

解析元数据是在分析仪前端完成的。通过 [DOMParser](https://developer.mozilla.org/zh-CN/docs/Web/API/DOMParser) 解析 HTML，提取 `<head>` 中的所有元素，遍历查找目标元数据。

遍历是有必要的，因为协议规定的一些元数据可以重复提供并被视作列表，比如各种 tag；甚至连 `og:image` 理论上都可以重复提供多张，再为每一张图片提供 `og:image:width`、`og:image:height` 和 `og:image:alt`。

::message{level=warning}
分析仪暂时不会支持多张图片之类的边界情况，目前的实现默认了只提供一张 `og:image`，并且实际上没有用到图片的宽高；但标签列表是支持的。
::

经过格式化的 HTML 文档也会显示在分析仪中。注意由于 HTML 文档的体量，展开并查看文档可能会导致页面性能下降。

### 图片抓取

浏览器对于 `<img>` 标签中的跨域图片是不会报跨域错误的，但是网站 B 可能会设置 :term-tip-anti-hotlinking ，这会阻止网站 A 使用 `<img>` 直接引用网站 B 的静态资源，比如 `og:image` 图像。

不同于同源策略由浏览器执行，防盗链是网站服务器执行的保护措施。对于简单的、最常见的防盗链，我们同样需要通过后端进行中转。

还记得芒果客栈实现了两个运行在云的端点嘛？第二个端点就是负责图像代理的。比如分析页页面下方示例当中的豆瓣，其静态图片 `og:image` 就需要通过后端中转。

中转的本质是使用 [Fetch API](https://developer.mozilla.org/zh-CN/docs/Web/API/Window/fetch)，将 `referrer` 设置为一个与网站 B 同源的地址。也就是：

```typescript [fetch-img.get.ts]
const url = "https://example.com/path/to/image.png"
const origin = "https://example.com/any/path"

await fetch(url, {
  headers: {
    'User-Agent': 'Mozilla/5.0 (compatible; mango-js-analyzer)',
    accept: 'image/*,*/*;q=0.8',
    referer: origin
  },
  redirect: 'follow',
  signal: AbortSignal.timeout(10_000)  // 10 秒超时
})
```

`User-Agent` 也可以修改成浏览器常用的代理，不过一般而言如果只是为了跳过防盗链，是没有必要的。

这段 Fetch API 在浏览器中也是可以运行并成功获取图片的，只是将 `await fetch()` 的返回应用给文档中的 `<img>` 元素会带来不必要的复杂度。相比而言，使用 Nuxt 的后端做一个中转是更符合直觉也更易维护的。

嘛，并非所有网站或者 CDN 设置防盗链，所以分析仪对 `<img>` 做了一个错误时 fallback，优先尝试直接跨域引用，回退到后端代理。

另外，理论上 `og:video` 也存在类似的问题，但考虑到 CloudFlare Worker 对免费使用的潜在限制，目前并未对 `og:video` 实现相同的后端中转。

### 视频预览

视频预览的规范行为是 `og:video` 提供指向视频媒体的 URL，`og:video:type` 提供 MIME 类型。然而，许多视频网站会提供 HTML 播放器链接以供嵌入，类型为 `text/html`。

对于视频，只需要使用 `<video>` 标签做内联播放即可；对于 HTML 播放器，需要使用 `<iframe>` 做嵌入。

虽然 `<video>` 中可以存在多个子节点用于依次降级，但是 `<iframe>` 在 `<video>` 中属于边界外的情况。分析仪使用 v-if 指令进行分支处理以避免这种情况。

## 结语

从现况来看，开放图谱协议早期的设想并没有完全实现，或者说几乎只实现了一小撮。

毕竟讲道理，没有人会想在社交媒体中分享的电影卡片上查看电影的完整演职员、编导演列表。

另外，复杂的结构化数据有诸如 `json-ld` 之类的结构化表达方式，只需要一个 `<script>` 标签即可包含多条 `<meta>` 才能包含的信息。于是这些以 `og:` 开头的数据渐渐失宠，许多网站也不再为每个页面提供它们，许多社媒也不再完整爬取它们。

不过倒也不至于一点意思都没有。
